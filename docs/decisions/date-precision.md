# 决策：时间按精度截断，不再伪造时刻

## 背景（2026-10-18 实测）

`date` 一律输出 `YYYY-MM-DD HH:mm`，但 Bing 页面根本没有绝对时间：

- 静态页只有「2026年8月17日」→ 我们补 `00:00`；
- 近期页只有「6 天之前」「8 小时」→ 按 `nowMs` 反推，**分钟位继承「现在」的分钟位**。

证据：同一分钟内发起的查询里，所有「x 小时前」条目共享 `:10`；两个不同视频的
`published` 都是 `2026-08-19 06:50`；同一条 qianwenai.com 结果在不同时刻是
`08:50/06:50`、`08:10/07:10`。

## 决策

`date` / `published` / `time` **按精度截断**，并各自新增 `*Precision`：

| 原文                           | 输出               | precision |
| ------------------------------ | ------------------ | --------- |
| `2026年8月17日` / `2026-09-20` | `2026-08-17`       | `day`     |
| `6 天之前` / `1 天前`          | `2026-10-11`       | `day`     |
| `10 小时之前` / `8 小时`       | `2026-10-17 02`    | `hour`    |
| `5 分钟之前`                   | `2026-10-17 11:55` | `minute`  |

- 值 = 按精度截断（day→10 位、hour→13 位、minute→16 位），**不再补零伪造时刻**。
- 前缀可比：字典序仍等于时间序，排序不需要解析成 Date。
- 误差上限是一个精度单位（day 精度 ±1 天，hour ±1 小时）。

## 语义边界（必须写清）

`date` 是 **Bing 的页面收录/更新日**，不是内容所指事件的发生时间；
**很多条目本来就没有该字段**（缺失 = Bing 没给，不是「没有日期」）。

因此它**只能做排序参考，不足以当过滤判据**：按「最近 7 天」过滤会丢掉所有
无 date 的条目，而把「没有 date」当「不满足时间条件」是错的。

## 明确不做

- ❌ 不加 `host` 字段：`url` 里已经有页面地址，`new URL(url).hostname` 永远正确，
  再加一个字段只是重复信息（`site` 的错标不影响判断——模型看 url 即可）。
- ❌ 不做「时间过滤」「独立源计数」之类的断言/派生字段：
  缺失值让这类计算没有确定答案，库替调用方算只会把错误传下去。
- ❌ 不做可信度打分/官方优先（同 [verdict-retirement.md](verdict-retirement.md)）。
- ❌ 不保留「6 天之前」这类原文：精度字段已足够表达不确定性。

## 代价

**Breaking change**：`date` 不再是固定 16 位。把 `date` 当 `YYYY-MM-DD HH:mm`
解析的调用方要改（本仓库测试、回归脚本已同步）。

## 验证

- `pnpm test:offline`：202 项通过（含精度形状断言，见 `tests/offline/parsers.test.ts` 的「日期前缀」与「相对时间换算」两组）
- `pnpm test:live`：51 项（38 pass / 13 skip）
- `pnpm test:offline` 的 `tests/offline/samples.test.ts`：硬性项「有 date 无 precision」必须为 0（实测 0）
- 真人抽查：两个不同 B 站视频的 `published` 都是 `2026-08-19 [day]`，
  不再共享 `06:50` 这种瞬间。

> 当年的 `date-prefix-check.ts` 已删除（2026-10-24）：
> 它用**源码切片**提取函数来断言，重构后切片失效。同样的断言现在由
> `tests/offline/parsers.test.ts` 直接 import `src/utils/time.ts` 覆盖。
> 这是「脚本迁进 node:test」的第一个成功先例，2026-10-24 起成为统一做法。
