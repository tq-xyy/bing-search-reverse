# 决策：rdr 必须作为第二遍独立请求

## 结论

拿到填充页（~400KB）而非骨架页（~100KB）的决定性条件是：
**先发一次普通请求，紧接着发一次带 `rdr=1&rdrig=<IG>` 的请求**。

两者是**联合条件**，不能合并，也不能只发后者。

## 证据

骨架高发期同刻实测（对照组排除了顺序效应）：

| 形态                        | 填充页   |
| --------------------------- | -------- |
| 三连单请求（无 rdr）        | 0/9      |
| 单请求 → rdr → rdr          | 9/9      |
| 单请求 → rdr → 单请求       | 骨/填/骨 |
| 两段（首遍 + rdr）          | 6/6      |
| **只发一次带 rdr=1 的请求** | **0/6**  |

最后一行是最重要的：跳过首遍直接发 rdr，得到的是骨架页。
说明 rdr 不是独立开关，它依赖"本会话刚发生过一次普通搜索"。

## 曾被推翻的两次

### 第一次：误判为冗余（已回滚）

在低骨架率时段测到"关闭 rdr 也 72/72 正常"，据此判定 rdr 冗余并删除。
随后在骨架高发期立刻回归。

**原因是无区分度基线**：低降级率时段的对照里，两组都正常，测不出差异。
这就是为什么本项目反复强调不能用"低降级率时段的结论"否定某条路径。

### 第二次：误判为可合并（已回滚）

曾把两段合并成一段（只发带 rdr 的那次），当时测到"100% 填充"。
后来发现**那些探针跑在仍含两段逻辑的副本上**，所谓 reuse 模式并未真正去掉
首遍的服务端效果。修正探针后复测为 0/6。

## 另一条已知必要条件

`form=QBLH` 是 rdr 被接受的另一个前提。缺 form 时 rdr 被拒 → 骨架页。
