# 决策：退役裁决体系

## 退役了什么

从 `src/index.ts` 删除了：`status` / `fallbackQuery` / `verdict` / `degraded` / `garbage`，
以及全部降级检测、可信度断言、缩减查询推测逻辑。

对外契约只剩一句话：**`pages` 就是 Bing 的返回**。

## 为什么

### 1. 判据本身不成立

曾经的判据是“体积”和“`b_algo` 计数”。但实测发现：

- 骨架页（~100KB）的结果标题**同样精准匹配完整查询**，与填充页无质量差异；
- 二者的差异只在**模块丰富度**（分页、相关搜索、答案卡），不是结果可信度；
- 因此体积与计数都不能作为降级判据，只有内容相关性可以。

### 2. 降级窗口不是二值开关

“降级窗口秒级开合”的表象实际是**概率漂移**（约 10%~100% 缓慢变化）。
同刻并发请求彼此独立。这意味着“现在降级了吗”这个问题没有稳定答案。

### 3. 下游需要的是结果，不是判断

下游（chatxt 等）拿到结果后自己判断相关性，比库替它判断更准。
库多做一层“可信度断言”，只会把错误判断传递下去。

## 保留了什么

- rdr 第二遍请求（必要路径，见 [rdr-two-pass.md](rdr-two-pass.md)）
- HVE cookie
- 网络级重试（5xx/超时等**真实故障**，与“结果质量”无关）

## 失败语义

重试耗尽后返回空 `pages`（不抛错），调用方以 `pages.length === 0` 判定。

## 教训

早先的实现里，“是否降级”的判断逻辑占了约 40% 的代码量，
而这些代码**从来没有被证明比“直接返回结果”更准**。
