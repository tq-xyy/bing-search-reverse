# 决策：绝不带 `first` 参数

## 背景

用户报告“bing.ts 与浏览器结果逐条相同，但没有 AI Overview”。
排查方向先是 UA、请求头、cookie——全部排除后，发现差异在 URL 的一个小参数上。

## 证据

同一会话、同一请求头、同一 cookie，只改 URL：

| URL            | 响应体积 | b_ans | AI Overview |
| -------------- | -------- | ----- | ----------- |
| 无 `first`     | 407KB    | 77    | ✅          |
| `first=1`      | 107KB    | 0     | ❌          |
| `first=0`      | 105KB    | 0     | ❌          |
| `first=2`      | 107KB    | 0     | ❌          |
| `first=`（空） | 107KB    | 0     | ❌          |

三个查询（经济应用数学基础 / Kubernetes Pod 调度 原理 / 民族团结法）全部复现。

## 机制

`first` 本是分页参数（从第几条开始），但 Bing 以它的**存在**判定
“这是一次翻页/后续请求”，因而跳过首屏才有的答案卡与富化模块。

浏览器首次导航的 URL 里没有 `first`，所以有 AI Overview。

## 后果

删掉了 `&first=1`。注意此前一直认为`first=1`是“安全的默认值”——
它看起来只是“从第 1 条开始”，语义上等价于不带。

## 教训

**“结果条目对”不等于“路径对”**。这个 bug 的表现是“结果完全正确，只是少了一个模块”，
所以长期没有被发现。评估一条请求路径时，不能只看主结果是否匹配，
还要看**富化模块的覆盖率**。

## 相关

本库不做翻页：`first` 只出现在翻页请求里，而翻页不在对外契约内
（`pagination` 字段已于 2026-10 删除）。
