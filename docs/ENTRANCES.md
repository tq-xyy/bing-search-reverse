# 两个入口：国内版与国际版

`searchByBing(query, { bingEnterance })` 的两个取值。本文回答三件事：
它们**在协议上差别在哪**、**检索质量谁更好**、**该默认哪个**。

## 一、机制：它们不是两套页面

**国际版 = 国内版 SSR 页面 + URL 上的 `ensearch=1`。** 没有第二套模板，
解析器不需要任何分支。这条结论来自 CDP 真实鼠标事件观测——
`#est_cn` / `#est_en` 是两个 div，页面上没有可抄的 href，
`element.click()` 不触发导航，必须 `Input.dispatchMouseEvent`，抓到的导航是：

```
GET https://cn.bing.com/search?q=<q>&FORM=BESBTB&rdr=1&rdrig=<IG>&ensearch=1
```

同一个查询、同一个会话，只差 `ensearch=1` 时服务端行为：

|                    | 国内版                         | 国际版                                    |
| ------------------ | ------------------------------ | ----------------------------------------- |
| `<html lang>`      | `zh`                           | `en`                                      |
| `<title>`          | `动量定理 - 搜索`              | `动量定理 - Search`                       |
| 主结果来源         | 国内站为主                     | 国际站为主                                |
| 单页 `ck/a` 跳转数 | 0                              | **40–66**                                 |
| 服务端改写 cookie  | `SRCHHPGUSR=SRCHLANG=zh-Hans…` | `SRCHHPGUSR=SRCHLANG=en&…&IG=<国际版 IG>` |
| 页面结构           | 同一套 SSR                     | 同一套 SSR                                |

### 1.1 四个必须照做的事实

**① 唯一内容开关是 `ensearch=1`。** 去掉它拿回中文界面，加上它拿回英文界面，
服务端连 `SRCHHPGUSR` 里的语言与 IG 都换掉。没有别的参数影响入口。

**② rdr 不是必需。** 直接 `/search?q=…&ensearch=1` 首遍就是填充页（8 个查询 320–532KB）。
模块仍保留「首遍骨架 → rdr 兜底」的既有序列，第二遍自动带着 `ensearch=1`。

**③ PAA 的 Feed/Language 随查询语言变化，与入口无关。** 中文查询走
`urlpostwebzhchs` / `zh_chs`，英文查询走 `urlpostweben` / `en`。
这两个值本来就从页面内联的 `AnswerFetcher(...)` 里提取，所以入口切换不需要改一行代码。

**④ 会话握手不区分入口。** 两个入口都从 `cn.bing.com/` 首页进去——
浏览器里点「国际版」也是从国内首页进的。所以不存在「国际版要用另一套 cookie」。

### 1.2 唯一必须写代码的地方：外链形态

国际版单页 40–66 处外链包着 `/ck/a?...&u=a1<base64url>`，国内版约 0~10%。
所以**取链接必须统一走一个出口**，而不是在每个字段处各自补全：

```
resolveBingUrl(href)
  1. /ck/a 且 u 以 a1 开头 → base64url 解码 → 得真实 URL
  2. 解出的若是站内相对路径（/images/search?…）→ 补 https://cn.bing.com
  3. 普通相对路径 → 补站点基址
  4. 已是绝对地址 → 原样返回
  5. 解不出（没有 u、u 不以 a1 开头）→ 原样返回，不猜、不抛错
  幂等：解过的 URL 再解一次不变
```

违规写法是「在某个字段处自己拼 `toAbsoluteUrl`」——那样国际版的视频卡、
图片卡、富卡片全会漏解，因为它们的 href 也是 `ck/a`。

这条由 `tests/offline/international.test.ts` 用 4 份真实响应锁住：
断言「样本里原本确实包着 `ck/a`」（证明还原不是空转）+ 「四份样本的解析结果都没有 `ck/a` 残留」。

## 二、入口选择：默认值与推测逻辑

```ts
// 中国大陆与港澳台 → cn，其余 → international
const CN_TIMEZONES = new Set([
    'Asia/Shanghai',
    'Asia/Chongqing',
    'Asia/Harbin',
    'Asia/Urumqi',
    'Asia/Kashgar',
    'PRC',
    'Asia/Hong_Kong',
    'Asia/Macau',
    'Asia/Taipei',
])

function resolveEntrance(explicit, timeZone) {
    if (explicit === 'cn' || explicit === 'international') return explicit
    return CN_TIMEZONES.has(timeZone) ? 'cn' : 'international'
}
```

**显式传 `bingEnterance` 永远优先。** 时区推测只是一个缺省值，
而且它给出的答案在数据上并不成立（见 §四）。

## 三、检索质量：两个入口的真实差别

这一节只回答「Bing 返回的结果谁更好」，**不掺入 token、PDF 转换、模型选页**这些下游因素。
全部指标只用搜索结果列表与答案引用的 URL。

数据来源：20 题 × 2 入口（5 领域各 4 题），2026-10-27 一次运行。
**Bing 有服务端灰度，同词跑两次都不一样，所以这些数字只在当时的条件下成立。**

### 3.1 四个纯搜索指标：三项打平

| 指标           | 定义                                          | 国内版          | 国际版           | 判定     |
| -------------- | --------------------------------------------- | --------------- | ---------------- | -------- |
| 一手源密度     | 答案引用的 URL 里，官方站/原典/原文全文的占比 | 34%（37/110）   | 33%（32/96）     | 打平     |
| 关键页递送速度 | 首搜 top5 里就含最终被引用的页的比例          | 60%（12/20）    | **68%（13/19）** | 国际略优 |
| 搜索结果覆盖率 | 答案引用中出现在任一搜索 top5 里的占比        | 63.6%（70/110） | 64.6%（62/96）   | 打平     |
| 命中名次       | 关键页首次出现时的平均名次                    | 2.1             | 2.3              | 打平     |

### 3.2 结果池成分：完全不看模型

**总数上打平，但这是全体平均的错觉。** 分领域后指纹完全不同。

## 四、结论与判据

| 领域            | 该用哪个   | 机制                                                                                                    |
| --------------- | ---------- | ------------------------------------------------------------------------------------------------------- |
| 编程 / 技术文档 | **国际版** | rfc-editor / doc.rust-lang / sqlite.org / docs.python.org 在国际版排得更前；国内版常被 CSDN、掘金先占位 |
| 外国文学        | **国际版** | 差距最大。Standard Ebooks / Gutenberg / Wikisource / litcharts 只在国际版池子里出现                     |
| 中国史 / 古籍   | **国内版** | 识典古籍、维基文库、24shi.wiki 的位次更稳（但两边都能进）                                               |
| 数学 / 形式化   | **国内版** | 中文数学术语的召回更准；国际版更容易掉进 HandWiki 这类百科                                              |
| 非遗 / 地方文化 | 打平       | 两边都进得了 ihchina.cn                                                                                 |

**判据不是「题面有没有英文」，也不是「中文主题用国内版」。**
前者回放只有 12 对 7 错；后者与数据相反——中国史是国际版 4:0 全胜的一段。
真正的判据是**你要的东西在哪一类信源里**：

> **要英文原典（RFC / 官方文档 / 英文原作全文）→ 国际版。**
> **要中文术语的学术解释（数学概念、古籍原文）→ 国内版。**

### 4.1 一个必须承认的天花板：文学题都不行

文学类的一手率：国内 8% / 国际 18%，但**两边池子里的一手源都只有 4% / 10%**。
也就是说：

> **文学题的原作全文在两个入口里都不足 10%，国际版只是「没那么糟」。**

这解释了为什么文学类答案大量依赖二手解读（豆瓣、LitCharts、eNotes）——
**不是模型不用原文，是 Bing 根本不把原文排上来**。

换入口解决不了这个问题。要做就得加**站点定向**能力：
识别「这是文学查询」后直接去 Gutenberg / Standard Ebooks / Wikisource 找原文，
而不是指望 Bing 的排序。这是库层面的能力缺口。

## 五、AI 摘要：`kind` 有两种，覆盖率不对称

`overview.kind` 是 `cht`（AI 深度答案，`.cht_text`）或 `gs`（生成式摘要，`.gs_text`）。
同 10 道中文查询的结果：

| 入口   | cht   | gs  | 无  |
| ------ | ----- | --- | --- |
| 国内版 | **1** | 7   | 2   |
| 国际版 | **0** | 4   | 6   |

**国际版在中文查询上拿不到 `cht`，`gs` 也只有国内版的一半多。**

按语言拆 A/B 那批的搜索级覆盖率（n=215 次搜索）：

| 入口   | 中文查询 | 英文查询 |
| ------ | -------- | -------- |
| 国内版 | 33%      | 26%      |
| 国际版 | **11%**  | 26%      |

**分歧只在中文查询上**（33% vs 11%）；英文查询两边一样（26%）。
英文查询时国际版并不吃亏——它本来就在答英文题。

### 5.1 但摘要不省轮次

这是最容易被误读的一条，记录反证：

| 检验                           | 结果                                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------------------- |
| 均轮次                         | 国内版 **7.9** / 国际版 **7.3**（国内版反而多 0.6 轮）                                   |
| 同题配对（一边有摘要、一边无） | 有摘要的一边更省 **4** 题 / 更贵 **4** 题                                                |
| 拿到摘要后第 2 轮动作          | 国内版 8 个「首搜有摘要」的 run 里，**6 个第一个动作是抓取**，没有一个「读完摘要直接答」 |
| 入口内分层                     | 有摘要 7.1 轮 vs 无摘要 8.2 轮——**这是选择效应**（Bing 只给容易题配摘要），不是因果      |

最硬的反例：**hist-2 国内版有 overview，却是 12 轮 473,854 token**（全批第 3 贵）。
摘要在旁边看着，它照样抓了 9 页、照样写四波事件分层。

**摘要不省轮次。** 它让模型「先知道该抓什么」，但抓取动作照旧，而这件事 snippet 也能做。

### 5.2 摘要也不该当质量信号

2026-10-23 的对照里，模糊查询的 overview 命中率反而更高（6/10 vs 5/10），
但其中 2 条内容是错的、1 条混入明确错误条目。
**它看起来像「直接答案」，比没有更误导。**

真实用例：ich-1 国内版的答案里自己写了——
「搜到的 AI 摘要里有一些具体百分比数字（如“识谱准确率 37%→68%”），未见可靠原始出处，我未采用」。

## 六、相关搜索：国内版的真实优势

8 个当代中文实用领域各 1 题（医保 / 住房 / 交通 / 教育 / 消费 / 税务 / 社保 / 办事）：

| 指标            | 国内版     | 国际版    |
| --------------- | ---------- | --------- |
| 平均结果条数    | 10.4       | 10.0      |
| gov.cn 占比     | 13.3%      | **21.3%** |
| 前 3 条含官方站 | 3/8        | 3/8       |
| **相关搜索**    | **均 7.0** | 均 2.3    |
| AI 摘要覆盖     | **88%**    | 63%       |

**国际版给的 gov.cn 反而更多**（21.3% vs 13.3%）。门诊慢特病那题，
国际版前 6 条里 5 条是政府站，国内版前 6 条有 2 条搜狐、1 条腾讯新闻、1 条百度健康。

所以国内版在实用题上的优势**不是排序**，是两件「省一轮」的事：

| 优势     | 数据                                        | 对实用的意义                         |
| -------- | ------------------------------------------- | ------------------------------------ |
| 相关搜索 | 7.0 vs 2.3（每题都有 vs 8 题里有 6 题是 0） | 用户问得不精确时，有一栏可点的下一步 |
| AI 摘要  | 88% vs 63%                                  | 「怎么办」类问题，摘要往往直接给流程 |

实用查询的用户不想读长文，只想拿到步骤；深度研究题不需要「省一轮」，需要「读原文」。
**这是两者真正的分界线。**

## 七、PAA 与相关搜索的稳定性

PAA 是服务端灰度，**不能当判据**：

| 查询                         | 国内版 PAA(有答案) | 国际版 PAA(有答案) |
| ---------------------------- | ------------------ | ------------------ |
| `SQLite WAL checkpoint`      | 0(0)               | 4(4)               |
| `Python 3.13 free-threading` | 0(0)               | 4(4) → 复跑 0(0)   |
| `what is HTTP/3 QPACK`       | 0(0)               | 4(4)               |

同一句英文查询、同一入口、隔几分钟跑两次，PAA 就从 4 条变 0 条。
**真正稳定的是相关搜索**（12 词对照里 57 vs 9 条）。

### 8.1 这个分布怎么解释

1. **中文主题基本打平**（非遗 1:1，2 平）。两边都能进非遗网、识典古籍、百度百科。
2. **中国古代史是国际版唯一全胜的一段**（4:0）。同样的识典古籍、维基文库两版都能进，
   差别在执行：国际版更倾向直接抓《汉书》《魏书》《元史》的原文页整段引用。
3. **外国文学是国际版的稳定优势**（2 胜 2 平）。Standard Ebooks、LitCharts、Gutenberg
   在国际版常排前 3；国内版要先绕豆瓣与书评站，经常只拿到摘要。
4. **编程是「原站排名」的差别**（2 胜 2 平）。rfc-editor / doc.rust-lang / sqlite.org
   在国际版排得更前；国内版常被 CSDN、掘金先占位。
5. **数学是唯一国内版占优的领域**（3:0，另 1 题无效）。但这是 20 题里最不稳定的一段：
   math-3 的垃圾结果、math-1/math-3 各烧掉 400 万 token，说明这个「优势」是靠反复改写硬磨出来的。

## 九、已知边界

1. **服务端灰度。** PAA / overview / 图片卡不是每次都有。测试只断言「出现时能解析」，
   不承诺覆盖率。Bing 的排序同词跑两次都不一样，本文所有数字都只在当时条件下成立。
2. **时区推测只是推测。** 中国大陆时区 → 国内版，其余 → 国际版。
   要确定行为请显式传 `bingEnterance`。
3. **`ck/a` 解码边界。** 只解 `/ck/a` 且 `u` 以 `a1` 开头的形态；
   解不出时原样返回，不猜、不抛错。
4. **两个入口共用同一套会话、解析器与错误模型。** 入口只影响搜索 URL 上的一个参数，
   不影响任何解析逻辑。这意味着**新组件只需要在一个入口上验证**，
   但**必须用国际版样本验证 `ck/a` 还原**（国内版样本里往往没有 `ck/a`，测不出漏解）。
